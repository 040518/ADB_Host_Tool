- 窗口标题、工具栏、启动日志和「关于」页显示 MUXO+。旧版 COM5 串口设置与 3 条 SSH 历史配置仍可读取。

## 2026-11-09 · v2.3.6 COM5 实机收发与波形横轴

- 通过 CH343 的 COM5，以 115200、8N1、无流控打开香橙派调试串口。上位机命令模板发出的查询返回 `/dev/ttyAMA0`，验证双向收发。

- 波形新增样本序号、刻度和横轴标题，滚轮缩放时刻度跟随可见样本窗口。实测图显示八条曲线及独立通道配色。证据为本地 `COM5_2.3.6_LIVE_TEST.log` 与 `screenshots/COM5_OrangePi_8_channels_v2.3.6.png`。
- 界面 119 项、核心 39 项通过，核心测试中 USB ADB 设备操作因无设备跳过。

## 2026-11-09 · v2.3.5 启动位置与后台线程稳定性

- 四份 v2.3.3 Windows 转储均在 `QThread::~QThread` 终止。人为延长后台任务返回前的时间，可在旧版复现线程仍在运行时被销毁的错误及退出码 `0xc0000409`。现在由线程的 `finished` 信号触发界面回调和清理，分批并发提交的 1,500 项任务均正确交付结果。
- 启动窗口按鼠标所在屏幕的可用区域居中，计算尺寸时计入原生标题栏和边框，并为高 DPI 下的还原偏差留出边距。延迟激活只负责切到前台。
- 界面检查 119 项、核心 39 项、端点 17 项、连接历史 11 项、光标 7 项、终端历史 4 项通过。Ubuntu 真机 SSH 连接下，65 秒内完成 65 次设备刷新。测试时没有在线 ADB 设备，RK3568 和香橙派的 SSH 端口不可达。
- 两台显示器上分别通过 100%、125%、150%、200% 缩放的窗口边界、最大化和还原检查。打包版开启每秒设备刷新，持续运行 390 秒后正常关闭，退出码 0，测试进程已清理。

### 3.1 已知限制（已实测复现）

PyInstaller **onefile** 在该超长中文路径下无法启动，报：

```
[PYI-xxxx:ERROR] Could not create temporary directory!
```

- 复现路径：`<较深的中文工程路径>\dist\ADB_Host_Tool.exe`
- 同一文件复制到以下位置**均能正常运行**：桌面、磁盘根目录、
  工程构建目录、独立测试目录、包含中文的目录
- 结论：属于 PyInstaller onefile 解包机制对特定深层中文路径的限制，不是程序本身缺陷。
- **交付位置为桌面（ASCII 短路径），已验证可用。**
  若用户把它移到很深的含中文目录后启动失败，把 exe 移回桌面/根目录即可。

## 5. 本次重构中发现并修复的问题

| # | 问题 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | `ab.quote()` 调用直接抛 `NameError: shlex` | 从旧代码拆分 `core/adb_backend.py` 时漏了 `import shlex` | 补上导入；该函数用于所有设备端路径引号，属阻断性缺陷 |
| 2 | 远程模式下「发送数据」写不到设备 | 把 Windows 临时文件路径交给了 Ubuntu 上的 adb | 改为 SFTP 写到 Ubuntu 临时文件 → 远端 `adb push` → 追加时再 `cat >>` |
| 3 | 远程模式下「写入 stdin」无效 | 旧实现残留，命令拼接错误 | 改为先把数据写到 Ubuntu，再 `cat file \| <命令>` |
| 4 | 远程模式下「截图」取不回文件 | `adb pull` 的目标写成了 Windows 路径 | 先 pull 到 Ubuntu 临时文件，再经 SFTP 取回本机 |
| 5 | 下拉框箭头渲染成白色方块 | QSS 未提供 `down-arrow` 图片 | 生成 `chevron_*.svg` 并在 QSS 中引用（绝对路径） |
| 6 | 图标箭头在小尺寸下几乎不可见 | SVG 笔画 1.6px 缩到 8px 后过细 | 小尺寸图标笔画加粗到 2.8 |
| 7 | 设置页控件被拉伸成整行长条 | 表单直接铺满窗口宽度 | 表单放入最大宽度 700 的容器并限制控件宽度 |
| 8 | 分隔条上出现 Qt 原生抓手圆点 | Fusion 风格自绘 | 自定义 `FlatSplitter`，只画一条纯色线 |
