# v2.3.1 三端文件互传、独立 SSH 与连接历史

日期：2026-11-08。

## 使用变化

- 文件页左右两栏均可独立选择 Windows、Ubuntu / SSH 目标、ADB；通过跨栏拖拽或复制按钮传输文件、目录。Windows ↔ SSH 不依赖 ADB，连接 SSH 不再替换 Windows 文件栏。
- 终端与摄像头支持自动、SSH 目标、ADB 三种目标选择；自动模式 ADB 优先，无 ADB 时使用当前 SSH 主机。若要看香橙派的 USB 摄像头，应连接香橙派的 SSH 地址。
- SSH 终端每个标签独立持久，支持已有历史、选择、补全与剪贴板操作。SSH 摄像头直接用 FFmpeg V4L2 与 SSH 二进制通道，不使用 ADB；SSH 与 ADB 的方向设置独立保存。
- SSH 对话框新增“新建连接”。保存时按用户名、地址、端口更新同一目标，不同目标追加，修复新主机覆盖当前选中记录的问题。多窗口保存会合并最新磁盘记录，切换选项不会覆盖其他窗口更新的密码。
- SSH 配置原子写入，并保留最近 10 份备份，位于本机 `%APPDATA%/AdbHostTool/ssh_profiles.backup-*.json`，与原配置一样包含用户选择保存的密码，不属于源码仓库。

## 真实环境验证

1. Windows ↔ Ubuntu SSH：二进制 SHA256 与嵌套文件夹一致，测试期间禁止 ADB 调用。
2. 直接 SSH PTY 执行唯一标记命令成功，不经过 ADB；SSH 重命名在正确文件系统执行。
3. 独立 SSH 二进制通道解码 6 帧合成 MJPEG 成功，不将此算作摄像头硬件验收。
4. 用户接通 Ubuntu 上的 ADB 后，Ubuntu ↔ ADB、Windows ↔ ADB（经 SSH 暂存中转）文件及目录往返通过。覆盖中文、空格、单引号名称与任意二进制字节。六个方向均有实机证据。
5. 香橙派 SSH 登录成功，USB 2.0 Camera 被识别为 `/dev/video0`、`/dev/video1`。测试账户加入 `video` 组并重新登录后，摄像头节点可访问。
6. 修复 GNU setsid fork 后 SSH channel 提前报告退出的问题，直接 SSH 启动增加 `-w`，确保长连接等待采集结束。最终 640×480 实测 6 秒收到 151 帧，界面约 30.0 FPS，真实 JPEG 解码、保存和停止清理通过，所有 ADB 调用均被禁止。
7. 1280×720 同样解码、显示、保存与停止成功，当前约 16.7 FPS。高分辨率优先传输原生 MJPEG 以减轻 ARM 编码负担，不支持时回退编码；640×480 保留本设备实测更快的原始采集后编码路径。原生 MJPEG 的独立板端 60 帧短测本身也约 17 FPS，不将软件或码流中声明的 30 FPS 当作实测。
8. 复测停止阶段发现一次 Qt 测试进程退出异常，已统一管理采集线程所有权，直到线程结束才释放，关闭时先等待清理；补充自动回归。最终 640×480、1280×720 的完整进程均退出码 0。
9. 摄像头测试只清理自己创建的 PID/进程组。未自动停止其他摄像头应用、修改摄像头驱动、固件或网络。

证据：`ENDPOINT_LIVE_TEST.txt`、本地 `SSH_CAMERA_FINAL_TEST.log`、`CAMERA_PERMISSIONS_2.3.0.log`、`SSH_CAMERA_720P_TEST.log`、`CAMERA_RATE_CHECK.log`。真实摄像头图片位于被 Git 忽略的 `docs/screenshots/`，不公开发布。

Windows 本机 USB 直连 ADB 只通过模拟与序列号回归，未替代为物理验收；六方向实机中的 ADB 位于 Ubuntu。未进行摄像头长时运行、掉线恢复或完整双板项目阶段验收。
